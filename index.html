작동 원리

정적으로 읽고, 동적으로 찌른다

두 계층이 후보를 만들고, AI가 실제 소스와 응답을 읽어 한 번 더 판정한다. 기계가 올린 후보를 그대로 믿지 않는 것이 이 도구의 핵심이다.

정적 탐지

SAST

소스를 읽기만 하므로 실행 중인 앱이 필요 없고 완전히 안전하다. 스택(Spring 모던 / JSP 레거시)을 자동 감지해 스택별 룰로 후보를 도출한다.

detecting-* · 9종 semgrep 우선 없으면 grep-fallback

동적 악용

DAST

실행 중인 스테이징/로컬에만 실제 페이로드를 발사해 "정말 뚫리는가"를 확정한다. 기본은 비파괴(탐지 페이로드만).

exploiting-* · 6종 scope_guard 게이트 비파괴 기본
입력 소스 · 실행 중 대상

소스 트리(필수)와 스테이징/로컬 URL(선택).

1차 · 기계 후보 도출

정적은 semgrep→grep, 동적은 게이트 통과 후 페이로드. 결과 = 후보(candidates).

2차 · AI 컨텍스트 검증

실제 소스·응답을 읽어 오탐을 제거한다. csrf().disable()이 STATELESS면 의도된 예외로 판정.

판정 확정 / 미확정
vulnerable secure needs-runtime needs-confirmation undetermined

scope_guard — fail-closed

동적 발사는 안전 게이트를 통과해야만 실행된다. 운영으로 보이는 대상(prod·www·공인 IP)은 코드로 차단하고 즉시 멈춘다.

후보 0건 ≠ 안전

grep 폴백은 recall 한계가 있다. gx-security는 0건을 "안전"으로 과대표기하지 않고, 진짜 음성인지 폴백 경고인지 구분해 정직하게 보고한다.

질문 → 발동 → 발견

어떻게 물으면 무엇을 발견하나

왼쪽 질문을 눌러 보라. 그 한마디가 어떤 커맨드·스킬을 발동하고 무엇을 찾아내는지 보여준다. 아래는 실제 프로젝트(sef-2026)에서 나온 값이다.

집행 신호가 있는 건을 기계가 임의로 지우지 않는다. 판정은 소스를 읽은 AI가 내린다.

취약 패턴
${}

MyBatis 문자열 치환 — 입력이 쿼리에 그대로 박힌다.

안전 패턴
#{}

파라미터 바인딩 — sef는 이 방식만 사용한다.

결론: 0건. 억지로 만들지 않은 진짜 음성(true negative)이며, 과대표기하지 않는다.

발동 /gx-security:gx-pentest 동적 exploiting-*

실행 중인 스테이징/로컬에 실제 페이로드를 발사

발견 · 발사 절차스테이징 · 권한 테스트

scope_guard — fail-closed 통과

대상이 스테이징/로컬임을 확인한 뒤에만 발사. 운영이면 여기서 차단된다.

실제 페이로드 발사

BFLA(일반 사용자 토큰 → 관리자 API) · IDOR · SQLi · XSS.

미확정이면 사람에게

상태코드·반사만으로 판단이 안 서면 evidence_expectation 카드를 띄우고, 사람이 실행·확인한다(AskUserQuestion).

권한 있는 사내 테스트 전용. 기본 비파괴이며, 데이터 변조·삭제는 별도 승인이 필요하다.

스킬 16 · 오케스트레이터 1 / 정적 9 / 동적 6

무엇을 묻고, 무엇을 발견하나

스킬은 메뉴가 아니라 어휘다. 질문에 담긴 의도를 AI가 읽어 맞는 스킬을 발동한다. 아래는 그 어휘집이다.

오케스트레이터 · 1

auditing-web-application-security

소스 경로(필수)와 실행 URL(선택)을 받아, 9종 정적 스캐너를 일괄로 돌리고 대상이 있으면 동적까지 통합해 하나의 리포트로 낸다.

이 프로젝트 전체 점검해줘 → 정적 9종 + (URL 있으면) 동적을 한 번에. 심각도순 4요소 리포트(취약점·이유·공격법·해결법 + Evidence).

정적 탐지 detecting-* · 9

소스만 읽음 · 앱 불필요 · 완전 안전
CSRF

detecting-csrf-vulnerabilities

CSRF 막혀 있어?

상태변경 엔드포인트의 토큰 보호 유무를 판정. csrf().disable()이 STATELESS면 의도된 예외로 본다.

XSS

detecting-xss-vulnerabilities

XSS 있어? 프론트도

반사·저장·DOM XSS + 프론트엔드 Vue v-html 미새니타이즈까지.

SQL Injection

detecting-sql-injection

SQL 인젝션 있어?

파라미터 바인딩 없이 문자열로 조립되는 쿼리. MyBatis 치환 vs 바인딩을 구분.

File Upload

detecting-file-upload-vulnerabilities

업로드로 웹쉘 되나?

확장자 화이트리스트 부재·매직바이트 미검증·웹루트 내부 저장 (CWE-434).

Path Traversal

detecting-path-traversal

임의 파일 읽혀?

다운로드·뷰어에서 ../로 WEB-INF/web.xml·/etc/passwd 접근 (CWE-22).

Broken Access Control

detecting-broken-access-control

남의 데이터 보여?

IDOR·BFLA·강제 브라우징. 소유권 미검증·@PreAuthorize 누락.

Auth / Session / JWT

detecting-auth-session-weaknesses

세션·JWT 튼튼해?

세션 고정·약한 해시·JWT 설정 오류·쿠키 보안속성(Secure/HttpOnly/SameSite) 누락.

Sensitive Data

detecting-sensitive-data-exposure

시크릿·개인정보 샜어?

하드코딩 시크릿(DB PW·API 키)·주민번호/이메일 평문·응답 DTO 과다 노출.

SSRF / Open Redirect

detecting-ssrf-and-open-redirect

내부망 찌를 수 있어?

검증 없이 서버측 HTTP 요청에 쓰이는 사용자 URL(RestTemplate·WebClient) + 오픈 리다이렉트.

동적 악용 exploiting-* · 6

실행 중 스테이징/로컬만 · scope_guard · 비파괴 기본
SQL Injection

exploiting-sql-injection

진짜 데이터 빠져?

후보 URL·파라미터에 boolean/time-based PoC 또는 sqlmap을 발사해 악용을 확정.

XSS

exploiting-xss-vulnerabilities

스크립트 진짜 실행돼?

고유 마커 주입 + Playwright로 브라우저 실제 실행 확인(저장형·DOM).

Broken Access Control

exploiting-broken-access-control

관리자 API 뚫려?

일반 사용자 토큰으로 관리자 API 호출(BFLA)·타인 토큰으로 A의 리소스(IDOR).

Auth / Session

exploiting-auth-session

토큰 위조돼?

토큰 base64 변조(alg=none·서명 제거·역할·만료)·로그아웃 후 재사용 점검.

SSRF / Open Redirect

exploiting-ssrf-and-open-redirect

콜백 돌아와?

루프백에 OOB canary 리스너를 띄우고 콜백 수신으로 블라인드 SSRF까지 확정.

Path Traversal / Upload

exploiting-path-traversal-upload

파일 실제로 읽혀?

../ 주입 → 응답 본문의 파일 시그니처(/etc/passwd·web.xml)로 인밴드 검증(읽기 전용).

사용법

세 커맨드, 혹은 그냥 질문

커맨드를 정확히 쳐도 되고, 자연어로 물어도 된다. 어느 쪽이든 같은 스킬을 발동한다. 안전 게이트는 항상 먼저 걸린다.

/gx-security:gx-diagnose

정적 · 안전

소스만 읽어 취약점 후보를 진단한다. 실행 중인 앱이 필요 없다.

<소스경로> [종류: csrf|xss|sqli|…]

자연어 이 소스 접근통제만 정적으로 봐줘

/gx-security:gx-audit

통합 · 정적+동적

9종 정적을 일괄로 돌리고, 대상 URL을 주면 동적 모의침투까지 이어 통합 리포트를 낸다.

<소스경로> [대상URL]

자연어 이 프로젝트 전체 점검해줘

/gx-security:gx-pentest

동적 · 권한 필요

실행 중인 스테이징/로컬에 실제 공격을 발사해 악용을 확정한다. 자사 소유·격리 대상만.

<대상URL> [sqli|xss] [--param 이름]

자연어 스테이징에 SQLi 실제로 뚫어봐

정적 진단 — 안전, 앱 불필요

# 소스 전체 9종 정적 진단
/gx-security:gx-diagnose D:\SQ\sqisoft-sef-2026

# 특정 종류만 (예: 프론트 XSS)
/gx-security:gx-diagnose D:\SQ\GSEED\source\Gseed_Web_Renew xss

# 자연어로도 같은 스킬이 발동한다
> 이 소스 정적으로 전체 점검해줘

동적 모의침투 — 안전 게이트가 먼저

# 0) 발사 전 범위 확인 — fail-closed. 운영이면 여기서 차단
python tools/scope_guard.py "http://localhost:8080/board?id=1"

# 1) 통과하면 발사 (SQLi, 파라미터 id)
/gx-security:gx-pentest http://localhost:8080/board?id=1 sqli --param id

# 통합으로 한 번에: 소스 + 대상 URL
/gx-security:gx-audit D:\SQ\sqisoft-sef-2026 http://localhost:8080

안전 게이트 — 늘 먼저 걸린다

tools/scope_guard.py가 운영(prod·www·공인 IP) 대상을 코드로 차단한다(fail-closed). 대상이 떠 있지 않으면 게이트가 되묻고(AskUserQuestion), 자격증명은 트랜스크립트가 아니라 --creds-stdin/--*-env로 전달한다. 기본은 비파괴다. 데이터 변조·삭제는 --allow-destructive + 사람 승인이 있어야만 실행된다.
