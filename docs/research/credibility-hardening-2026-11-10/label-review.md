# 합성 후보 탐지 라벨 검토

2026-11-10. 별도 모델 에이전트가 [28개 사례](../../../tests/fixtures/rule-quality/cases.json), 참조 합성 소스, 해당 12개 규칙의 메시지·패턴을 읽고 검토했다. 라벨 작성 에이전트와 분리한 모델 검토이며, 사람의 독립 보안 평가나 외부 벤치마크가 아니다. 이 검토에서 앱 컴파일·기동·브라우저·DB·공격 재현이나 엔진 평가를 다시 실행하지 않았다.

**후보 경고 기대값이라는 범위에서는 이진 라벨을 뒤집을 명백한 오류를 찾지 못했다.** 다만 양성을 실제 취약점, 음성을 안전한 앱으로 부르는 것은 근거가 부족하다. 특히 `access-vuln`은 자원에 접근하지 않으며, 단순 음성 5개는 관련 기능을 아예 포함하지 않는다. SQL helper와 DOMPurify는 현재 구문의 매칭 여부를 복사한 정답이 아니라, 탐지기에서 기대하는 위험 보존·잡음 감소 방향의 사례다.

아래의 유지 판단은 **주어진 전제하의 후보 기대값**에 관한 것이다. 취약/안전이라는 파일명과 주석은 검증 결과가 아니다.

|---|---|---|
| auth-vuln | 경고 | 유지. password 인자를 MD5로 처리하는 약한 비밀번호 해시 후보다. 실제 저장·인증 사용은 소스 조각에 없다. |
| auth-safe | 없음 | 유지. 산술 함수이며 인증 기능이 없다. 안전한 비밀번호 저장을 구별하는 시험은 아니다. |
| access-vuln | 경고 | 유지하되 ID 매개변수 단서로만 해석한다. 상수 `x`를 반환하므로 IDOR나 다른 사용자의 데이터 접근을 입증하지 않는다. |
| access-safe | 없음 | 유지. 상수 반환이며 객체 접근 기능이 없다. 소유권 검사의 효과를 평가하지 않는다. |
| csrf-vuln | 경고 | 유지. CSRF 비활성화 후보다. 쿠키 등 자동 전달 인증과 상태 변경 기능이 있어야 실제 CSRF 위험을 평가할 수 있다. |
| csrf-safe | 없음 | 유지. 기본 CSRF 설정을 사용하는 구문 대조군이다. 배포의 필터 적용·요청 예외까지 검증하지 않았다. |
| xss-vuln | 경고 | 유지. 요청값을 응답 writer에 직접 전달한다. HTML 해석 가능한 응답 컨텍스트와 실제 호출이 위험의 전제다. |
| xss-safe | 없음 | 유지. HTML 텍스트 출력용 인코딩을 적용한 대조군이다. 정상 Encoder와 HTML 텍스트 컨텍스트가 전제이며 JS·속성 컨텍스트의 보장은 아니다. |
| upload-vuln | 경고 | 유지. 원본 파일명을 저장 경로에 사용한다. 사용자가 파일명에 영향을 주고 상위 검증이 없다는 조건에서 경로·덮어쓰기 위험 후보다. |
| upload-safe | 없음 | 유지. 산술 함수이며 업로드가 없다. 안전한 파일 저장 구현을 검사하는 사례는 아니다. |
| ssrf-vuln | 경고 | 유지. 변수 URL로 서버 요청을 수행한다. 인자 이름만으로 외부 입력을 확정할 수 없으며, 호출 경로·허용 목록·네트워크 도달성을 확인해야 한다. |
| ssrf-safe | 없음 | 유지. 산술 함수이며 외부 요청이 없다. 허용 목록을 적용한 HTTP 호출을 구별하는 시험은 아니다. |

| secrets-vuln | 경고 | 유지. properties의 평문 password 설정 패턴이다. 값은 합성이며 실제 유효한 자격증명이라는 뜻은 아니다. |

## 해석 시 바로잡을 점

Spring의 `validateAllowCredentials`는 `allowCredentials=true`와 `allowedOrigins=*`의 조합을 검증 오류로 거부한다고 명시한다. 이 검증 API는 5.3부터 제공된다. 따라서 두 CORS 양성을 “자격증명이 포함된 요청을 허용하여 정보가 유출된다”로 확정하면 안 된다. 실제 프레임워크 버전·설정 적용·응답 헤더와 브라우저 결과를 별도로 확인해야 한다. [Spring 공식 API](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/web/cors/CorsConfiguration.html#validateAllowCredentials())

실측 TP 13·FP 1·FN 1·TN 13은 이 후보 기대값과 검사 출력 사이의 집계다. 이 문서 검토로 실제 취약성의 정밀도·재현율이나 사업부 프로젝트 전체의 탐지율이 검증된 것은 아니다. DOMPurify의 FP와 helper SQL의 FN을 알려진 한계로 남긴 점은 유지하되, 두 값의 런타임 전제도 함께 보관한다.

## 다음 정답표의 개선 항목

1. 단순 음성 5개에 더해 동일 기능에 실제 방어를 적용한 대조군을 만든다. 특히 객체 소유권, 업로드 저장 경계, SSRF 목적지 제한, 경로 요소 기반 containment를 포함한다.
2. 후보 탐지 기대값과 실제 취약성 정답을 별도 필드로 둔다. 위험을 판정할 수 없는 항목은 미확정으로 남긴다.
3. CSRF는 쿠키 인증·헤더 인증, CORS는 지원 버전·동일 객체 alias·실제 응답, SSRF는 외부 입력·허용 목록을 포함한 실행 가능한 쌍으로 평가한다.
4. SQL helper는 실제 쿼리 호출까지, DOMPurify는 고정 버전·설정의 브라우저 결과까지 검증하고 정상 입력도 함께 시험한다.
5. 사람이 합의한 정답과 숨겨진 실프로젝트 표본을 별도 관리한다. 이번 모델 검토와 자체 합성 결과를 외부 공신력이나 보안 인증으로 표현하지 않는다.
