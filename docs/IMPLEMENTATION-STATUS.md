# GX Security 0.10.2 프리뷰 구현·검증 현황

개발자가 실행하고 QA·PM이 결과를 공유하는 사전 보안 점검 도구입니다. 2026-11-10 로컬 0.10.2 작업본 기준이며 조직의 출시 승인이나 보안 적합성 인증을 대신하지 않습니다. 원격 배포·GitHub Pages 반영은 별도 상태입니다.

## 제공하는 기능

- 통합 `gx-security`에서 준비·출시·변경·재검증·기존 결과 설명으로 연결합니다. 프로젝트마다 setup이나 설정 파일을 만들 필요는 없습니다.
- Semgrep·OSV-Scanner·Gitleaks를 연결하고 엔진·자료·검사 범위가 부족하면 미완료로 표시합니다. 고정 실행 환경과 최신 승인 DB·확정 의존성 자료는 별도 준비가 필요합니다.
- SEF public/private/혼합 구성과 권한·토큰 목적·객체 귀속·경로·파일 경계를 관찰합니다. MyBatis 호출별 치환과 제한된 SQL 바인딩·Vue/DOMPurify 문맥은 검토 근거로 제공합니다.
- 질문이 필요한 업무 의도는 호스트 AI가 사용자에게 확인하고, 답변 후 소스·설정·반대 근거를 추가 조사합니다. `discuss`는 기록과 입력 연결을 검증하며 자체적으로 AI 분석이나 공격을 하지 않습니다.
- 질문·답변·조사는 원래 실행·발견·소스·범위·분석기와 연결합니다. 전체 입력 변경·잘못된 근거 라인·동시 수정 충돌을 거부하고 불변 이력을 남깁니다.
- 사용자 설명, 의도와 구현의 일치·불일치·미확정을 별도 공유합니다. 답변은 공식 반증·예외·출시 통과 권한이 아닙니다.
- 원래 검사 보고서와 질문·답변 공유본을 분리합니다. 저장된 보고서 설명만 요청하면 새 검사·설치·질문을 시작하지 않습니다.
- 일반 SAST 후보가 재검사에서 사라져도 자동 해결하지 않습니다. 현재 소스·범위·결과에 연결된 독립 검토와 보호된 수정 검증 승인이 필요합니다.
- SEF 포크임을 알 수 있으면 별도 setup 없이 기대 프레임워크를 전달해 필수 계약을 확인합니다. 일반 프로젝트에는 일괄 적용하지 않습니다.
- Windows 실행기는 외부 정책·오프라인 DB·검토 기록을 읽기 전용으로 연결합니다. Codex 등록기는 전체 bundle을 보존하고 기존 사용자 스킬을 덮어쓰지 않습니다.
- 검사 루트 직하의 자동 생성 `.claude/worktrees` 작업 복사본을 구분하고 제외 경로·범위 계약을 기록합니다. 복사본 자체를 검사 대상으로 선택하거나 일반 업무 폴더가 `worktrees`인 경우, 중첩 모듈 안의 같은 경로는 계속 검사합니다.

## 0.10.2에서 확인한 범위

| 검증 | 실제 확인·제한 |
|---|---|
| 규칙 후보 탐지 평가 | 28개 사례의 후보 탐지 기대값 대비 **TP 13 / FP 1 / FN 1 / TN 13**. 실제 취약성·악용 성공 정답표가 아님 |
| 평가 규칙 범위 | 전체 **88개 중 12개 규칙**에 대한 한정 평가. 나머지 규칙의 정밀도·재현율은 이 결과로 추정하지 않음 |
| Codex 등록기 행동 회귀 | 임시 bundle/skills 폴더에서 6개 통과: 링크·실제 경로/리소스 유지, 재실행, 기존 스킬/다른 bundle 보존, 불완전 bundle 거절, WhatIf 무변경 |
| 새 호스트 행동 평가 | [8개 fixture와 독립 평가 지침](research/credibility-hardening-2026-11-10/host-behavior-review.md) 제공. **실제 호스트 평가 미완료** |
| Windows 전체 자동 회귀 | **1,180 passed / 15 skipped / 314 subtests passed**. `GXSEC_NO_SEMGREP=1` 경로, 2026-11-10. 실제 엔진 평가는 위 별도 행과 구분 |
| 후속 경로 경계 회귀 | 폴더 끝 구분자를 포함한 출력 중첩·정책·DB·정상 실행 **9개 통과**. 전체 회귀와 겹치므로 합산하지 않음 |
| 입력 무결성 진단 회귀 | 실제 소스 변경, 수집 오류 단독·변경 동반, 정상 실행을 구분한 **4개 통과**. 수집 미완료를 실제 소스 변경으로 오인하지 않고 미완료 판정 유지 |
| 관리 작업 복사본 범위 회귀 | 정확 루트 제외, 중첩 경로·일반 폴더·직접 선택한 checkout 보존, 범위 계약과 사본 변조 감지를 포함한 **110개 통과**. 독립 검토의 핵심 **20개 통과**, 범위가 겹치므로 합산하지 않음 |
| 원격 필수 검사 | [구현 커밋의 CI](https://github.com/bs-koo/gx-security/actions/runs/42734769053): Windows **1,181 passed / 16 skipped**, Ubuntu **1,120 passed / 77 skipped**, 고정 Semgrep **1,133 passed / 64 skipped**. 환경별 범위가 겹치므로 합산하지 않음 |
| 고정 Linux 패키지 | 같은 CI의 원본 Dockerfile 빌드·네트워크 차단 준비 확인·실제 엔진 시험 통과. 합성 의존성 취약 버전 `BLOCK` → 수정 버전 `PASS`와 종료 근거 검증 |
| 실제 사용자 등록·OS 설치 | 이번 등록기 검증에서는 수행하지 않음 |

규칙 평가의 FP 1건·FN 1건을 숨기지 않습니다. 28개에는 기능이 없는 단순 음성 대조군 5개와 객체 데이터 반환이 없는 접근통제 후보도 포함됩니다. 이 집계는 탐지기 동작 회귀이며 실제 위험 판정 정확도를 입증하지 않습니다. 사업부 프로젝트 전체 정확도, 전체 88개 규칙의 성능 또는 외부 보안 인증으로 일반화할 수 없습니다. 미지원 구문·배포 정책·권한 의도는 추가 검토가 필요합니다. 과거 경고 건수 감소 역시 정밀도 개선율을 입증하지 않습니다.

## 한계와 준비 조건

기본은 정적 점검입니다. 전역 데이터 흐름·모든 동적 표현식·배포 정책을 완전하게 해석하지 않습니다. 동적 검증에는 승인된 대상·합성 계정과 데이터·격리 환경·별도 보호 정책이 필요합니다. 선택 엔진의 실제 조직 환경 적용과 더 넓은 정확도·사용성 평가는 별도입니다.

공식 수정 완료 경로는 SAST/SEF의 보호된 검토와 SCA 재검사에 한정합니다. secrets/auth/authorization/dast의 종결 프로토콜은 미지원이며, 과거 `fixed-verified` 표시만 있는 경우 미완료로 처리합니다.

공개 저장소는 실행기·스킬·빌드 지침을 제공합니다. Docker 이미지가 공개 레지스트리에 게시되거나 도구·호스트 스킬이 자동 설치된다고 가정하지 않습니다. 최초 실행 환경과 호스트 등록이 필요합니다.
