# P3 커버리지 (v0.6.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 최신 스택(JWT+JSON REST)과 레거시(JSP)의 탐지 커버리지를 넓힌다 — SQLi/XSS가 JSON 바디 주입과 인증 뒤 화면을 다루고, 접근통제가 jsp-legacy 표적을 뽑도록 한다. v0.6.0 릴리스.

**Architecture:** `tools/dyn_session.request()`가 이미 `json_body`+`token`+`session`+리다이렉트 미추종을 통합 지원한다. attack_sqli/xss는 **인증 또는 JSON 모드일 때만 `dyn_session.request()`로 위임**하고 기존 GET/form 경로(requests/urllib)는 그대로 두어 하위호환을 지킨다. 접근통제는 `build_targets()`에 jsp 분기를 추가해 URL이 담긴 정적 후보를 표적화한다.

**Tech Stack:** Python 3.11 · requests · urllib · unittest

1. **점진적 위임(전면 리팩터 회피)**: attack_sqli/xss의 기존 `_send()`/`check_reflection()`의 GET·form 경로는 **그대로 유지**한다(기존 테스트가 `requests.get/post`·`_OPENER`를 하드 검증하므로). **인증 인자가 주어졌거나 `--content-type json`일 때만** `dyn_session.request(method, url, token=.., session=.., json_body=..)`로 발사한다. 판정 로직(마커 반사·시간지연 등)은 응답 dict만 소비하므로 발사 경로와 무관하게 재사용된다.
2. **자격증명 배선 재사용**: D3 인증 인자·해석은 P2에서 검증된 `attack_access.py`의 `_resolve_auth()`(bearer/cookie 분기)·`_apply_creds_and_profile()`(프로파일+`resolve_secret`+`--creds-stdin`) 패턴을 그대로 이식한다(신규 설계 금지, 이미 opus 승인된 로직).
3. **D6 최소 스펙**: `build_targets()`에 jsp 분기를 추가하되, **스니펫에 URL이 담긴 jsp 규칙만 표적화**한다 — `jsp-admin-url-exposure`(BFLA)·`jsp-state-changing-get-link`(BFLA). URL이 스니펫에 없는 규칙(`jsp-getparameter-id`·`jsp-isadmin-check`)과 web.xml `<url-pattern>` 표적은 `scan_access.py` 대공사가 선행돼야 하므로 **백로그**로 분리한다(로드맵 D6 범위 조정, §백로그 참조).

```python
def set_by_path(obj, path, value):
    """'data.query' 점 표기 경로에 value 설정(중간 dict 자동 생성). obj를 반환."""
    keys = path.split(".")
    cur = obj
    for key in keys[:-1]:
        nxt = cur.get(key)
        if not isinstance(nxt, dict):
            nxt = {}
            cur[key] = nxt
        cur = nxt
    cur[keys[-1]] = value
    return obj
```
