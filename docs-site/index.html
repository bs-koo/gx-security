SEF의 보안 경계를 살핍니다.

소스에서 public·private·mixed 기반을 관측하고, 근거가 부족하면 undetermined로 남깁니다. SEF가 아니어도 일반 검사는 이어갑니다.

다섯 보안 경계와 MyBatis의 include·property·SQL 바인딩·호출 문맥을 제한된 문법 범위에서 검토합니다.

문맥 분석은 검토 제안입니다. helper의 존재·기반 일치·미검출을 공식 검증·반증·출시 승인으로 바꾸지 않습니다. 동적 설정·생성 코드·배포 조건 등은 추가 검토가 필요할 수 있습니다.

시작 전에 자주 묻는 것

공개 버전을 설치하면 통합 요청을 바로 쓸 수 있나요?

2026-11-05 기준 공개 마켓플레이스는 0.8.2입니다. 이 페이지의 /gx-security:gx와 $gx-security 예시는 0.10 설치·등록 환경을 위한 미리보기입니다. 공개 0.8.2의 /gx-audit·/gx-diagnose·/gx-pentest 안내는 아래 공개 버전 사용법·레퍼런스에서 확인할 수 있습니다.

프로젝트마다 setup이나 설정 파일이 필요한가요?

별도 setup·init·설정 생성은 필수가 아닙니다. 기존 환경·설정·이력을 재사용하며, 설정이 없으면 기본값으로 진행합니다. 조직의 필수 입력과 보호된 정책은 별도로 충족해야 합니다. 기본 Windows Docker 경로는 외부 정책·DB mount를 자동 제공하지 않습니다.

매번 목적이나 설치 여부를 다시 묻나요?

“출시 전에 보안 점검해줘”처럼 목적과 대상이 분명하면 진행합니다. 목적 없는 단독 호출, 여러 검사 대상이나 재검증 항목 중 선택이 필요한 경우에만 짧게 확인합니다. 같은 범위에서 이미 받은 답과 설치 선택은 반복해서 묻지 않습니다.

“보안 점검해줘”가 서비스 공격까지 포함하나요?

일반·출시 전 요청의 기본값은 static-release입니다. 실행 중인 서비스에 능동 공격 요청을 보내지 않습니다. 동적 검사, 소스 수정, 외부 전송·배포는 현재 요청과 기존 정책의 권한 범위 안에서만 수행합니다.

보고서 설명을 요청해도 다시 검사하나요?

저장된 결과만 읽습니다. 준비 확인·새 스캔·설치·설정 생성을 시작하지 않으며, 당시의 시각·범위·판정을 유지해 설명합니다. 결과를 찾을 수 없으면 저장 위치를 확인합니다. 과거 보고서는 현재 소스의 새 검사 결과가 아닙니다.

후보가 사라지거나 건수가 0이면 안전한가요?

미검출만으로 안전이나 수정 완료를 확정하지 않습니다. 지원 범위와 필수 검사 완료 여부를 확인하고, 수정 후에는 원래 발견 ID·프로파일·상태를 연결해 재검증합니다. 문맥 제안과 정식 검토·승인 기록도 구분해서 읽어야 합니다.
